  <name>Task 1: Migrate encounterStore, vitalsStore, and refractionStore to real API</name>
  <files>store/encounterStore.ts, store/vitalsStore.ts, store/refractionStore.ts</files>
  <action>
**encounterStore.ts (API-01):**
1. Add `loadEncounter(encounterId: string)` action:
   - Set a `loadStatus: "loading"` field on the encounter state
   - Call `apiFetch<EncounterResponse>(`/api/encounters/${encounterId}`)` — this returns the full encounter with vitals, refractions, diagnoses, exam_findings inline (confirmed in research)
   - On success: populate encounter metadata (chiefComplaint, status, patientId, providerId, createdAt). Expose `patientId` on the encounter state shape — downstream `problemListStore.fetchProblems()` depends on this
   - On error: set `loadStatus: "error"` with error message
   - CRITICAL: Use `set()` directly to update state, NOT `initEncounter()`. The `persist` middleware means `initEncounter()`'s idempotency guard (`if (existing) return`) would skip the update when stale data is in localStorage. `loadEncounter()` must force-overwrite.
2. Remove any mock data imports or fallback patterns
3. Ensure `patientId` is a selector-accessible field: `useEncounterStore((s) => s.encounters[encId]?.patientId)`

**vitalsStore.ts (API-02):**
1. Add `loadVitals(encounterId: string)` action:
   - Set `saveStatus: "loading"` on the encounter's vitals state
   - Call `apiFetch<VitalsResponse>(`/api/encounters/${encounterId}/vitals`)` OR parse vitals from the encounter response if a single-fetch approach is used
   - On success: call `init(encounterId, vitalsData)` to populate draft/committed state
   - On error: set `saveStatus: "error"` with `errors: [{ field: "_load", message: "Could not load Vitals" }]`
   - Add retry: 2 retries for load (separate from save retries). On exhaustion, show error state per user decision
2. Remove the mock fallback catch block — the current pattern is `catch { await sleep(400); savedDraft = { ...draft, id: mock-id }; }`. Delete this entire catch body. Replace with real error handling: set `saveStatus: "error"`, populate errors array
3. Remove any manual snake_case payload construction — stores must send camelCase keys now. apiFetch() handles conversion transparently (per Plan 02-01). Audit the save function: if it manually builds `{ iop_od: ..., iop_os: ... }`, change to `{ iopOd: ..., iopOs: ... }`. The api-client converts to snake_case automatically.
4. Add `"loading"` to the VitalsSaveStatus type union

**refractionStore.ts (API-03):**
1. Add `loadRefractions(encounterId: string)` action:
   - Set loading state on the encounter's refraction state
   - Call `apiFetch(`/api/encounters/${encounterId}`)` and parse the `refractions` array from the response
   - The API returns `RefractionSummary[]` with flat fields (`odSphere`, `odCylinder`, etc. after camelization). Create a `refractionSummaryToDraft()` converter that maps flat fields to the nested `RefractionDraft` shape (`od.sphere`, `od.cylinder`, etc.)
   - Initialize each column from the converted data
2. Remove the mock fallback catch block in the save function
3. CRITICAL: Normalize all payload keys to camelCase. The store currently has a mix — some fields are already camelCase (`refractionType`, `isFinalRx`) but nested eye objects may have snake_case keys (`visual_acuity`). Normalize ALL to camelCase (`visualAcuity`). The api-client snakifyKeys handles conversion. This prevents the double-conversion pitfall identified in research.
4. Remove any `await new Promise(resolve => setTimeout(resolve, 400))` mock delay patterns
  </action>
