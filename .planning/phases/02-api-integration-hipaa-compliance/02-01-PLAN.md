  <files>lib/api-client.ts, lib/case-convert.ts</files>
  <action>
1. Create `lib/case-convert.ts` with four exported functions:
   - `toCamel(str: string): string` — converts `snake_case` to `camelCase` via regex `/_([a-z])/g`
   - `toSnake(str: string): string` — converts `camelCase` to `snake_case` via regex `/([A-Z])/g`
   - `camelizeKeys<T>(obj: unknown): T` — deep recursive: arrays, nested objects, primitives pass through
   - `snakifyKeys(obj: unknown): unknown` — deep recursive: arrays, nested objects, primitives pass through

2. Rewrite `lib/api-client.ts`:
   - Replace `import { supabase } from "./supabase"` with `import { createClient } from "@/lib/supabase/client"` (SSR-safe, per Phase 1 pattern)
   - Import `camelizeKeys`, `snakifyKeys` from `@/lib/case-convert`
   - Add `withRetry<T>(fn, retries, baseDelayMs): Promise<T>` — exponential backoff (500ms base -> 500, 1000, 2000ms)
   - Update `getAuthHeaders()` to use `createClient()` instead of legacy singleton
   - Update `apiFetch<T>` signature to accept `{ retries?: number }` in options (default 3)
   - In apiFetch body handling: if body is a string, parse JSON, run snakifyKeys, re-stringify. Wrap in try/catch to leave non-JSON bodies as-is
   - After successful response JSON parse: run `camelizeKeys<T>(json)` before returning
   - Wrap the fetch+response-handling in `withRetry()` with the configured retry count

CRITICAL: The existing `import { supabase } from "./supabase"` uses the legacy singleton. Per Phase 1 decision, all browser-side Supabase operations must use `createClient()` from `lib/supabase/client.ts`. This is API-08.

Do NOT import lodash for case conversion — the custom functions are sufficient for the narrow field set.
