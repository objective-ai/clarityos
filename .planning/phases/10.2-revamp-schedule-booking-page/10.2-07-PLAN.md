<task type="auto">
  <name>Task 2: Fix detail drawer — conditional render gate + close controls</name>
  <files>components/schedule/AppointmentDetailDrawer.tsx</files>
  <action>
  Three bugs in one file, all related to the drawer's open/close behavior:

  **Bug A — Drawer visible on page load (UAT test 4):**
  The drawer panel always renders in the DOM and relies solely on CSS `translate-x-full` to hide. During SSR hydration, the transform may not apply on first paint.

  Fix: Add an early return before the JSX (before line 100). If `!open && !appointment`, return `null`. This prevents rendering the drawer at all when nothing is selected. Keep the CSS transition for smooth animation when `open` toggles.

  Additionally, on the drawer panel div (line 113), add `pointer-events-none` when `!open` as defense-in-depth:
  ```
  ${open ? "translate-x-0" : "translate-x-full pointer-events-none"}
  ```

  **Bug B — No X button in empty state (UAT test 5):**
  The X/close button is inside the `appt ? (...)` ternary branch (around line 122-130 in the header). The empty state (lines 303-308) has no dismiss affordances.

  Fix: Move the X close button OUTSIDE the `appt` ternary. Place it as an absolutely-positioned button in the drawer panel div, before the ternary:
  ```tsx
  {/* Always-visible close button */}
  <button
    onClick={onClose}
    className="absolute top-4 right-4 z-10 p-1.5 rounded-md text-white/60 hover:text-white hover:bg-white/10 transition-colors"
    aria-label="Close drawer"
  >
    <X className="w-5 h-5" />
  </button>
  ```
  Remove the duplicate X button from inside the header section (the one inside `appt ? (...)`).

  **Bug C — ESC key not working (UAT test 5):**
  The ESC handler (line 66) is gated on `if (e.key === "Escape" && open)`. This is actually correct — the real issue is Bug A (drawer shouldn't be visible when `open` is false). Once Bug A is fixed, ESC will work when the drawer is truly open. No change needed for ESC handler.
  </action>
