# Phase 10.2 Plan 02: checked_in_at + Date Range Query Summary

checked_in_at TIMESTAMPTZ added to Appointment model via idempotent Alembic migration; backend list endpoint extended with date_from/date_to range support; Zustand store gains fetchWeekAppointments action.

## What Was Built

### checked_in_at (Task 1)

- **ORM:** `checked_in_at: Mapped[datetime | None]` added to `Appointment` class in `clinical.py`
- **Migration:** `0013_add_checked_in_at_to_appointments.py` uses `ALTER TABLE appointments ADD COLUMN IF NOT EXISTS checked_in_at TIMESTAMPTZ` for idempotency across dev (already exists) and production tenants
- **Schema:** `checked_in_at: datetime | None = None` added to `AppointmentResponse`
- **Route:** `check_in_patient` endpoint now sets `appt.checked_in_at = datetime.now(timezone.utc)` when status transitions to ARRIVED (only if not already set)
- **Response helper:** `_build_appointment_response` passes `checked_in_at=appt.checked_in_at`
- **TS type:** `checkedInAt: string | null` added to `Appointment` interface in `types/appointment.ts`

### Date Range Query + Store (Task 2)

- **Backend:** `list_appointments` now accepts optional `date_from` and `date_to` params alongside existing `date`
  - Range mode: validates `date_from <= date_to`, max 31 days, converts to UTC using clinic timezone
  - Single-day mode: existing behavior preserved (backward compatible)
  - Neither provided: 422 with clear error message
- **BFF:** No changes needed — `proxyToFastAPI` already forwards all GET query params via `forwardQuery=true`
- **Store:** `weekAppointments: Appointment[]`, `isLoadingWeek: boolean`, and `fetchWeekAppointments(startDate, endDate)` added to `appointmentStore`
