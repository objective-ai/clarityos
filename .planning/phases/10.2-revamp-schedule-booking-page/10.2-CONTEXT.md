# Phase 10.2: Revamp Schedule & Booking Page - Context

**Gathered:** 2026-04-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Modernize the staff-facing appointment scheduling UI (calendar navigation, appointment cards, booking flow, patient flow board) AND build the patient-facing public booking page using the existing backend. No changes to backend appointment logic — frontend revamp only (with minor BFF additions for slot availability if needed).

</domain>

<decisions>
## Implementation Decisions

### Calendar & Date Navigation
- Replace prev/today/next arrows + date input with a **horizontal week strip** at the top
- Week strip shows Mon-Sun with **count badges** under each day (total appointments)
- Arrow buttons to shift weeks left/right
- Clicking a day loads that day's appointments
- Keep single-day as the primary view — selected day in the strip is highlighted
- Add a **5th view mode: "Week"** — time-aligned grid with days as columns, shared time axis on the left (Google Calendar style)

### Appointment Card Redesign
- **Color-coded left border** by status (matches existing TimelineView/ClinicView pattern — colored left stripe)
- Compact layout: time, patient name, type, provider, insurance, chief complaint, status
- **Add wait time indicator** — show elapsed time since check-in for arrived patients (amber >15min, red >30min)
- **Add intake status icon** — small icon showing sent/submitted/not-sent status prominently on card
- **Clicking a card opens a side drawer/panel** with full appointment details, patient info summary, status history, and all actions
- Keep primary action button on the card itself (Check In / Start Exam / View Encounter) for quick access without opening drawer

### Booking Flow Improvements
- Convert booking modal to a **side drawer** (slide-in from right) for more space
- Replace manual time input with a **slot picker grid** — show available time slots based on provider's schedule, grey out occupied slots (hover shows who)
- Keep inline new-patient creation within the drawer
- **Overbooking:** Staff can always overbook — show conflict warning but don't block (current behavior preserved)
- **Recurring appointments: DEFERRED** — too complex for this phase, note for future

### Status Board & Patient Flow
- Add a **4th view mode: "Flow"** — Kanban-style patient flow board
- **4 columns:** Waiting (arrived), Pre-Test (in_pretest), In Exam (in_exam), Done (completed + finalized)
- **Upcoming section** above the board showing scheduled/confirmed appointments as a horizontal strip
- Cancelled/no-show hidden by default
- Wait time displayed on each card in the flow board (amber >15min, red >30min)
- **Auto-refresh via polling every 30 seconds** — no WebSocket needed
- **Drag-and-drop:** Claude's discretion — implement if complexity is reasonable, otherwise buttons-only

### Drawer Architecture
- **Claude's discretion** on single shared drawer vs two independent drawers
- Key constraint: appointment detail and booking need to coexist without confusion
- If shared: one drawer component switching between detail/booking modes
- If separate: booking drawer takes priority; clicking an appointment while booking closes booking first

### View Mode Persistence & Role Defaults
- **Role-based default views:**
  - Receptionist → Flow board (patient tracking)
  - Doctor → Clinic view (their provider column)
  - Technician → Flow board
  - Owner → List view (overview)
- User's explicit choice overrides role default and persists to localStorage
- 5 view modes total: List, Timeline, Clinic, Flow, Week

### Patient Self-Booking (Public Page)
- Build a **public booking page** at `/book/[slug]` — no authentication required
- Backend already exists: `public_booking.py` with `/info/`, `/availability/`, `/book/` endpoints
- **Step-by-step wizard:** 1) Select visit type → 2) Pick provider → 3) Choose date + time slot → 4) Enter patient info → 5) Confirm
- **Clean, light/white public-facing style** — NOT the internal glassmorphism aesthetic. Professional, accessible, mobile-friendly
- Uses clinic's accent color for branding
- Patient booking shows only truly available slots (no overbooking from patient side — backend already handles this)

### Mobile / Responsive
- **Basic responsive only** — ensure nothing breaks on tablet/mobile
- Week strip scrolls horizontally on small screens
- Drawers become full-screen overlays on mobile
- Flow board stacks columns vertically on narrow screens
- Full mobile-first redesign is Phase 13 scope

### Claude's Discretion
- Drawer architecture (shared vs separate)
- Drag-and-drop on flow board (implement if reasonable complexity)
- Loading skeleton designs
- Exact spacing, typography, animation details
- Error state handling patterns
- Week view column widths and responsive breakpoints

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **TimelineView** time-slot grid: Already implements 30-min slots with `ROW_HEIGHT`, `NowIndicator`, colored blocks — can be extended for week view columns
- **ClinicView** multi-column layout: Provider columns with `COL_MIN_WIDTH=180` — similar pattern needed for week view days
- **AppointmentCard** with OverflowMenu: Existing action patterns (status-dependent button + overflow menu) can be reused in flow board cards
- **BookAppointmentModal** patient search: Debounced search + autocomplete + inline new-patient — extract into the new booking drawer
- **Conflict detection** (`useMemo` in BookAppointmentModal): Already compares against provider's appointments — reuse for slot picker
- **STATUS_COLORS / STATUS_LABELS / STATUS_SHORT_LABELS**: Full status color system already defined in `types/appointment.ts`

### Established Patterns
- **View mode toggle**: Existing 3-mode toggle (list/timeline/clinic) with localStorage persistence — extend to 5 modes
- **Provider filter**: Staff list fetch + filter dropdown — already in schedule page
- **Date navigation**: `shiftDate()`, `clinicToday()`, `formatDateLong()` from `lib/timezone.ts` — reuse for week strip
- **Glassmorphism**: `glass-card`, `glass-input` CSS classes for internal views
- **Dynamic imports**: Timeline/Clinic/IntakeLinkModal use `next/dynamic` with loading skeletons

### Integration Points
- **appointmentStore.fetchAppointments(date, providerId)**: Currently fetches single day — may need new endpoint or client-side aggregation for week view
- **Public booking route**: Needs new Next.js page at `app/book/[slug]/page.tsx` (outside tenant layout)
- **Role detection**: `useEntitlements()` + session `app_metadata.role` — needed for role-based view defaults
- **BFF proxy**: Public booking endpoints may need BFF routes OR can be called directly (they're unauthenticated)

</code_context>

<specifics>
## Specific Ideas

- Week view should feel like Google Calendar — time-aligned grid, days as columns
- Flow board should feel like a Kanban board (Trello/Linear style) — cards in status columns
- Patient self-booking wizard should feel clean and professional — NOT the internal dark glassmorphism, but a light/white design
- Wait time indicators use amber (>15min) and red (>30min) color coding — urgency-based
- Slot picker shows availability visually — grey for occupied, clickable for available

</specifics>

<deferred>
## Deferred Ideas

- **Recurring appointments** — complex series management (edit one/all/future, conflict resolution across dates). Own phase.
- **Real-time WebSocket updates** — would replace 30s polling for instant status changes. Requires WebSocket infrastructure.
- **Full mobile-first redesign** — Phase 13 scope
- **Waitlist management** — when a slot opens up, notify patients on waitlist. Future phase.

</deferred>
