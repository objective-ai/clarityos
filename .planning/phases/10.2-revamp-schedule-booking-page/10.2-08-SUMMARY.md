# Phase 10.2 Plan 08: Public Booking Error Fix Summary

**One-liner:** Fixed "[object Object]" error in public booking confirm step by making dob/sex optional in Pydantic schema and unwrapping FastAPI 422 detail arrays into human-readable messages.

## Decisions Made

1. **dob/sex optional in PublicBookingRequest** — public booking wizard intentionally does not collect these fields; they are gathered via post-booking intake form.
2. **null over undefined** — frontend sends `null` explicitly so the field appears in the JSON body (undefined is silently dropped by JSON.stringify).
3. **Array error unwrapping** — FastAPI 422 returns `detail` as an array of `{loc, msg, type}` objects; the handler now maps each to `d.msg` and joins with ". " for a readable sentence.
