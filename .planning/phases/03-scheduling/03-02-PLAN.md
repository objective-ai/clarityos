    Follow the pattern from `encounterStore.ts` and `diagnosisStore.ts`:
    - State: `appointments: Appointment[]`, `selectedDate: string` (ISO date), `isLoading: boolean`, `error: string | null`
    - Actions:

      - `createAppointment(payload: AppointmentCreatePayload)`: POST /api/appointments, appends to list, returns created appointment
      - `updateAppointment(id: string, payload: AppointmentUpdatePayload)`: PATCH /api/appointments/{id}, updates in list
      - `cancelAppointment(id: string, reason: string)`: POST /api/appointments/{id}/cancel, updates in list
      - `checkIn(id: string)`: POST /api/appointments/{id}/check-in, updates status in list
      - `startExam(id: string)`: POST /api/appointments/{id}/start-exam, updates status in list, returns { encounterId, alreadyExisted }
      - `setSelectedDate(date: string)`: updates selectedDate
    - Use devtools middleware with name "ClarityOS/Appointments"
    - Export selector hooks: `useAppointments`, `useSelectedDate`, `useAppointmentLoading`
    - Error handling: try/catch with `err instanceof Error ? err.message : "..."` pattern
    - Mock fallback: When API fails, log error but don't crash (no mock data needed — just show empty state)

    **3. BFF proxy routes** — Follow the pattern from `app/api/audit-logs/route.ts`:
    Each route: createServerSupabaseClient() -> getUser() check -> getSession() for token -> forward to FASTAPI_URL with Authorization header.

    `app/api/appointments/route.ts`:
    - GET handler: forwards query params (date, provider_id) to FastAPI GET /api/appointments/
    - POST handler: forwards body to FastAPI POST /api/appointments/

    `app/api/appointments/[appointmentId]/route.ts`:
    - GET handler: forwards to FastAPI GET /api/appointments/{appointmentId}
    - PATCH handler: forwards body to FastAPI PATCH /api/appointments/{appointmentId}

    `app/api/appointments/[appointmentId]/check-in/route.ts`:
    - POST handler: forwards to FastAPI POST /api/appointments/{appointmentId}/check-in

    `app/api/appointments/[appointmentId]/start-exam/route.ts`:
    - POST handler: forwards to FastAPI POST /api/appointments/{appointmentId}/start-exam

    `app/api/appointments/[appointmentId]/cancel/route.ts`:
    - POST handler: forwards body to FastAPI POST /api/appointments/{appointmentId}/cancel

    **IMPORTANT**: Stores use `apiFetch()` which calls `NEXT_PUBLIC_API_URL` (FastAPI directly). BFF routes are only used for specific server-side needs (audit-logs, ai-scribe accept).
