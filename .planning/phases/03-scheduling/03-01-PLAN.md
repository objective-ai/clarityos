    Follow the pattern from `backend/schemas/encounter.py`. Create:

Compute end_time from start_time + duration_minutes in a model_validator.
    - `AppointmentUpdateRequest`: All fields optional. appointment_type, start_time, duration_minutes, chief_complaint, internal_notes. Recompute end_time if start_time or duration_minutes changes.
    - `AppointmentCancelRequest`: cancellation_reason (str, required, min_length=3)
    - `AppointmentResponse`: All fields from the model — id, tenant_id, patient_id, provider_id, booked_by_id, appointment_type, status, start_time, end_time, duration_minutes, chief_complaint, internal_notes, cancellation_reason, created_at, updated_at. Also include `patient_name` (str | None) and `provider_name` (str | None) for display.
    - `AppointmentListResponse`: items (list[AppointmentResponse]), total (int)
    - Use the `AppBaseModel` from `backend/schemas/common.py` as the base class (same pattern as encounter schemas).

  <action>
    **1. Create `backend/api/routes/appointment.py`** following the pattern from `encounter.py`:

    Import the standard dependencies: `APIRouter`, `Depends`, `HTTPException`, `Request`, `status`, `select`, `AsyncSession`, `log_action`, `require_permission`, `resolve_staff`, `TenantContext`, `get_db`, plus the Appointment and Encounter models, and the new schemas.

    Create `router = APIRouter()` and implement these endpoints:

    **POST /** — Create appointment
    - Permission: `MANAGE_APPOINTMENT`
    - Resolve staff via `resolve_staff` to get `booked_by_id`
    - Create Appointment row with tenant_id from context, status=SCHEDULED
    - Audit log: `AuditAction.CREATE`, resource_type="appointment"
    - Return `AppointmentResponse` with 201

    **GET /** — List appointments by date range
    - Permission: `VIEW_SCHEDULE`
    - Query params: `date` (required, ISO date string), `provider_id` (optional UUID filter)
    - Filter: `tenant_id` match, `start_time` between date 00:00 and date 23:59:59 (timezone-aware)
    - Eager-load patient (for patient_name) and provider staff (for provider_name)
    - Order by start_time ASC
    - Return `AppointmentListResponse`

    **GET /{appointment_id}** — Get single appointment
    - Permission: `VIEW_SCHEDULE`
    - Scope by tenant_id, eager-load patient and provider
    - Return `AppointmentResponse`

    **PATCH /{appointment_id}** — Update appointment
    - Permission: `MANAGE_APPOINTMENT`
    - Only allow updates when status is `SCHEDULED` or `CONFIRMED` (not after check-in)
    - Apply partial update from `AppointmentUpdateRequest`
    - Audit log: `AuditAction.UPDATE`
    - Return updated `AppointmentResponse`

    **POST /{appointment_id}/cancel** — Cancel appointment
    - Permission: `MANAGE_APPOINTMENT`
    - Require `AppointmentCancelRequest` body (cancellation_reason)
    - Set status to `CANCELLED`, set cancellation_reason
    - Audit log: `AuditAction.CANCEL_APPOINTMENT`
    - Return updated `AppointmentResponse`

    **POST /{appointment_id}/check-in** — Check in patient
    - Permission: `CHECK_IN_PATIENT`
    - Validate current status is `SCHEDULED` or `CONFIRMED` — else 409 Conflict
    - Set status to `ARRIVED` (maps to "checked_in" in frontend per CONTEXT.md simplified flow)
    - Audit log: `AuditAction.CHECK_IN`
    - Return updated `AppointmentResponse`

    **POST /{appointment_id}/start-exam** — Start exam (creates encounter)
    - Permission: `START_EXAM`
    - Validate current status is `ARRIVED` — else 409 Conflict ("Patient must be checked in first")
    - Check if an Encounter already exists with this appointment_id. If so, return 200 with `{ encounter_id: existing.id, already_existed: true }` (prevents duplicates)
    - Create new Encounter: patient_id from appointment, provider_id from appointment, appointment_id=appointment.id, encounter_date=today, chief_complaint copied from appointment's chief_complaint
    - Set appointment status to `IN_EXAM`
    - Audit log: `AuditAction.START_EXAM` with encounter_id in changes
    - Return `{ encounter_id: new_encounter.id, already_existed: false }` with 201

    **Helper function** `_build_appointment_response(appt, patient_name, provider_name)`:
    Map ORM Appointment to AppointmentResponse, including joined patient_name and provider_name.

    **2. Register router in `backend/main.py`**:
    - Import: `from backend.api.routes import appointment`
    - Add: `app.include_router(appointment.router, prefix="/api/appointments", tags=["Appointments"])`

    **Important conventions to follow:**
    - Every query must filter by `ctx.tenant_id` (multi-tenant isolation)
    - Use `resolve_staff` dependency to get the Staff record for the current user
    - Use `log_action()` after every successful mutation
    - Use `require_permission(ClinicalAction.XXX)` as Depends for RBAC
    - Return proper HTTP status codes: 201 for create, 200 for read/update, 409 for invalid transitions
  </action>
