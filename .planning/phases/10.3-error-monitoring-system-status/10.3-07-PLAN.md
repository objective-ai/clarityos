        # System Status

        Admin > System is an OWNER-only surface showing live platform health.

        ## Panels

        **Service Health** — FastAPI, Postgres, and Supabase Auth cards with a colored dot (green / amber / red), latency in ms, and a "last checked" timestamp. Backed by `GET /api/system/health` which runs a `SELECT 1` Postgres probe and a 2s timeout GET to Supabase's public `.well-known/openid-configuration`.

        **Recent Errors** — Last ~50 unresolved Sentry issues in the production environment, sourced directly from the Sentry REST API (no local mirror). Each row links out to the Sentry issue page. Token stays server-side via the BFF proxy with a 20s cache.

        **Uptime & Deploy** — 7-day uptime percentage computed as `count(all_green=true) / count(*)` over `system_health_samples`. Current deploy SHA is read from `GIT_SHA`. Samples are written every 60s by a FastAPI asyncio background task AND on every OWNER view.

        ## Refresh

        - Auto-poll: 30s (each panel)
        - Manual: "Refresh" button top-right of the section
        - "Updated HH:MM:SS" timestamp next to the Refresh button

        ## TopNav Health Dot

        A small colored dot to the left of ClockInButton in the TopNav, visible to OWNER only, polling `/api/system/health` every 60s. Click opens Admin > System. Color rollup: any dependency `down` → red; any `degraded` → amber; otherwise green.

        ## Alerting

        Sentry built-in email alerts are the sole alerting channel at launch. The alert rule "Any new issue in production" emails the OWNER and Duy. No Slack, no SMS, no pager.

        The status page itself is pull-based — it does NOT push alerts.

        ## PHI Safety

        Every Sentry event passes through `lib/sentry/phi-scrubber.ts` (Next.js) and `backend/core/sentry_scrubber.py` (FastAPI). These enforce a shared deny-list of patient identifiers, contact info, insurance data, and clinical free-text. Clinical routes (`/api/encounters`, `/api/patients`, `/api/ai-scribe`, `/api/claims`, `/api/vitals`, `/api/exam-findings`, `/api/superbills`) have their entire request body dropped before the event leaves the process.

        Sentry is **disabled in dev and Vercel preview** by design — test fixtures include synthetic PHI and must not leak to the cloud.

        ## Runbook

        - If ServiceHealth shows Postgres down: check Supabase Postgres dashboard, run `bash scripts/dev.sh ensure-api`.
        - If Supabase Auth shows degraded: check Supabase status page.
        - If Recent Errors is empty but you suspect issues: verify `SENTRY_API_TOKEN` is set in Vercel env and has scopes `org:read, project:read, event:read`.
        - If uptime drops during a deploy window: expected — the self-pinger is restarted; compute on a wider window if needed.
