# Phase 10.3: Error Monitoring & System Status - Research

**Researched:** 2026-04-21
**Domain:** Observability (Sentry JS + Python), Next.js 14 App Router instrumentation, FastAPI middleware, OWNER-only admin surface
**Confidence:** HIGH for codebase patterns (verified via grep); MEDIUM-HIGH for Sentry SDK shape (training-data knowledge current through mid-2025, flagged where version-sensitive)

## Summary

Phase 10.3 adds Sentry error capture on both runtimes and an OWNER-only System Status section inside the existing Admin page. The HIPAA-critical work is the `beforeSend` PHI scrubber — a deterministic, unit-testable function with a frozen deny-list that walks the Sentry event payload (data, breadcrumbs, request.query_string, request.data, request.url) and either redacts matching keys or drops whole fields for clinical routes. All other work (health endpoint, self-pinger, status cards, TopNav dot, Sentry REST proxy) is conventional Next.js/FastAPI wiring that reuses established phase-10.4 patterns (section registry, TopNav slot, BFF subtree, `public_booking.py` rate limiter).

The Sentry REST API (`GET /api/0/projects/{org}/{project}/issues/`) is the single source of truth for Recent Errors — no local `error_events` mirror (PHI risk). Uptime is computed from a new `system_health_samples` table in the `public` schema populated by a 60s FastAPI `asyncio` background task.

**Primary recommendation:** Build the scrubber first as a pure function with exhaustive unit tests (deny-list, nested dicts, arrays, URL query strings, clinical-route body-drop). Everything else is wiring — but the scrubber is the HIPAA seatbelt and must not regress.

**Sentry scope & PHI safety**

### Pattern 1: Next.js 14 Sentry init (3 config files)

**Next.js 14 still uses the three-file pattern** (`sentry.client.config.ts`, `sentry.server.config.ts`, `sentry.edge.config.ts`) with `withSentryConfig(nextConfig, sentryOpts)` in `next.config.mjs`. Newer SDKs additionally support a single `instrumentation.ts` hook; keep both — the installer wizard produces them.

```typescript
// sentry.client.config.ts
import * as Sentry from "@sentry/nextjs";
import { scrubEvent } from "@/lib/sentry/phi-scrubber";

const dsn = process.env.NEXT_PUBLIC_SENTRY_DSN;
const env = process.env.NEXT_PUBLIC_VERCEL_ENV; // 'production' | 'preview' | 'development'

if (dsn && env === "production") {
  Sentry.init({
    dsn,
    environment: "production",
    release: process.env.NEXT_PUBLIC_VERCEL_GIT_COMMIT_SHA,
    tracesSampleRate: 0.0,
    replaysSessionSampleRate: 0.0,
    replaysOnErrorSampleRate: 0.0,
    ignoreErrors: ["NEXT_REDIRECT"],
    beforeSend(event, hint) {
      return scrubEvent(event); // returns null to drop, or scrubbed event
    },
  });
}
```

`sentry.server.config.ts` and `sentry.edge.config.ts` mirror this with the non-public `SENTRY_DSN` and no replay options. The `environment === "production"` guard is the switch that keeps dev/preview silent.

### Pattern 2: FastAPI Sentry init (auto-integration)

```python
# backend/core/sentry_init.py
import os
import sentry_sdk
from sentry_sdk.integrations.fastapi import FastApiIntegration
from sentry_sdk.integrations.starlette import StarletteIntegration
from sentry_sdk.integrations.asyncio import AsyncioIntegration

from backend.core.sentry_scrubber import scrub_event

CLINICAL_PREFIXES = (
    "/api/encounters", "/api/patients", "/api/ai-scribe",
    "/api/claims", "/api/vitals", "/api/exam-findings", "/api/superbills",
)

def _before_send(event: dict, hint: dict) -> dict | None:
    # 1) ignore rules
    exc_info = hint.get("exc_info")
    if exc_info:
        exc_type, exc_value, _ = exc_info
        if exc_type.__name__ == "ClientDisconnect":
            return None
        if exc_type.__name__ == "HTTPException" and getattr(exc_value, "status_code", None) in (401, 403):
            return None

    # 2) clinical route body-drop
    request = event.get("request") or {}
    url_path = (request.get("url") or "").split("?")[0]
    # request.url is full URL; derive path
    from urllib.parse import urlparse
    path = urlparse(request.get("url", "")).path
    if any(path.startswith(p) for p in CLINICAL_PREFIXES):
        event.setdefault("tags", {})["route_type"] = "clinical"
        if "data" in request:
            del request["data"]  # drop body entirely

    # 3) deny-list scrub everywhere
    return scrub_event(event)

def init_sentry() -> None:
    dsn = os.getenv("SENTRY_DSN")
    env = os.getenv("SENTRY_ENVIRONMENT")
    if not dsn or env != "production":
        return
    sentry_sdk.init(
        dsn=dsn,
        environment="production",
        release=os.getenv("GIT_SHA"),
        traces_sample_rate=0.0,
        send_default_pii=False,  # critical — belt-and-suspenders
        max_request_body_size="small",  # hard cap even before scrub
        integrations=[
            StarletteIntegration(transaction_style="endpoint"),
            FastApiIntegration(transaction_style="endpoint"),
            AsyncioIntegration(),
        ],
        before_send=_before_send,
    )
```

Call `init_sentry()` in `backend/main.py` **immediately after `app = FastAPI(...)` and BEFORE `app.add_middleware(...)` / `app.include_router(...)`**. The SDK installs an ASGI middleware automatically when `StarletteIntegration` is active — no manual `add_middleware` needed.

### Anti-Patterns to Avoid

- **Hand-rolling regex-based PHI scrub** — key-based deny-list is deterministic and testable; regex is lossy and hard to reason about in review.
- **`sentry_sdk.init()` inside a request handler** — init runs once at startup; anywhere else is a bug.
- **Forwarding `SENTRY_API_TOKEN` to the browser** — must stay server-only in the BFF route.
- **Writing error payloads to a local DB table** — explicitly rejected in CONTEXT; re-examining this would regress the phase's HIPAA posture.
- **Running Sentry in dev** — fixtures include test patients; Sentry capture in dev could leak synthetic PHI to Sentry's cloud.
- **Skipping the scrubber on breadcrumbs** — breadcrumbs include every fetch URL and form submission. A URL like `/api/patients/123?mrn=XXXX` will leak without query-string scrub.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Error aggregation / dedup / counts | Custom error table with stacktrace hashing | Sentry Issues API | Sentry already groups by fingerprint, tracks counts, first/last seen — we'd reinvent 100+ engineer-years poorly |
| Sourcemap upload | Manual sourcemap hosting | `withSentryConfig` sourcemaps upload (uses `SENTRY_AUTH_TOKEN`) | Built into the Next.js SDK build step |
| Request context capture | Manual middleware | `StarletteIntegration` + `FastApiIntegration` | Auto-attaches request, user, transaction name |
| Alert emails | Custom SMTP pipeline | Sentry project alert rule | Already supported, configurable in Sentry UI |
| ASGI integration | Custom middleware with try/except | `FastApiIntegration` | Handles exception groups, background tasks, websocket disconnects |
| Rate limiter | New library | `public_booking.py` `_check_rate_limit` | Already proven; factor to shared util |

**Key insight:** Sentry is the industry-standard BAA-available error tracker for HIPAA. Everything we'd build would be a worse Sentry. Our job is scrub + wire, not build.

## Common Pitfalls

### Pitfall 1: PHI leaks via URL query strings
**What goes wrong:** A staff member browses `/api/patients?mrn=ABC123` and an error occurs. The URL ends up in `event.request.url` AND in every breadcrumb for the rest of the session.
**Why it happens:** Query-string scrub is often forgotten because devs think of "request data" as body-only.
**How to avoid:** Scrubber MUST parse `event.request.url` (Python) / `event.request.url` (JS), rewrite `?mrn=ABC123` → `?mrn=[Filtered]`, and apply the same treatment to every `breadcrumbs[].data.url`.
**Warning signs:** Scrubber unit tests that don't include a URL-with-query test case.

### Pitfall 2: Clinical route body-drop applied after general scrub
**What goes wrong:** General scrub doesn't know a field is PHI because it's named something innocuous (e.g. `value`, `content`). Clinical body-drop must happen unconditionally for those paths.
**Why it happens:** Scrubbing by key names can't catch PHI inside arbitrary JSON blobs.
**How to avoid:** Body-drop is a separate gate that runs FIRST, based on `request.url` path prefix. Only then does the deny-list scrubber walk remaining fields.
**Warning signs:** Any clinical-path error in Sentry that shows a non-empty `request.data` field.

### Pitfall 3: Sentry init runs in dev/preview
**What goes wrong:** Dev hits a bug, captures an event, synthetic PHI (test patient) ends up in Sentry prod org.
**Why it happens:** Default init runs unconditionally; `NODE_ENV` on Vercel preview is `production`.
**How to avoid:** Gate on `process.env.NEXT_PUBLIC_VERCEL_ENV === "production"` (Vercel sets this to `"preview"` on preview deploys — distinguishes the two). On backend, gate on `SENTRY_ENVIRONMENT=production`.
**Warning signs:** Any Sentry event from a URL containing `vercel.app` or `localhost`.

### Pitfall 4: Middleware order swallows exceptions before Sentry sees them
**What goes wrong:** Custom auth middleware catches `HTTPException` and returns a JSON 500 before Sentry's integration can record it.
**Why it happens:** FastAPI exception handlers run before ASGI middleware.
**How to avoid:** `StarletteIntegration` wraps the entire app; exceptions from route handlers propagate to the SDK. Don't add broad `try/except` in user middleware that suppresses exceptions. Test with an intentionally-failing route during verification.
**Warning signs:** Sentry issue count near zero in prod despite known outages.

### Pitfall 5: Self-pinger keeps running after hot reload
**What goes wrong:** In dev with `uvicorn --reload`, each reload spawns a new background task; soon you have 20 pingers writing samples.
**Why it happens:** `asyncio.create_task` doesn't get cancelled on module reload.
**How to avoid:** Guard the background task on `SENTRY_ENVIRONMENT == "production"` too. Also register a `@app.on_event("shutdown")` handler that cancels the task. Even simpler: skip dev entirely (this matches the Sentry init guard).
**Warning signs:** `system_health_samples` grows by >1 row/min locally.

### Pitfall 6: 7-day uptime window counts gaps as "down"
**What goes wrong:** Self-pinger stops (deploy, crash). When computing uptime, missing samples look like "no data" not "down" — but if we divide by expected samples, the gap reads as 100% down.
**Why it happens:** Sparse time-series data is ambiguous.
**How to avoid:** Define uptime as `count(all_green=true) / count(*)` over the window (only counts samples that WERE recorded). Publish a second metric "samples expected vs actual" so gaps are visible but don't poison uptime %. Document this decision in the VERIFICATION step.
**Warning signs:** Uptime drops to 0% during a deploy window.

### Pitfall 7: Recent Errors panel rate-limits Sentry
**What goes wrong:** 30s client poll × OWNER sessions × multiple tabs → hundreds of Sentry REST calls per hour. Sentry rate-limits at 40 req/s by default but per-org limits vary.
**Why it happens:** No server-side cache.
**How to avoid:** In `app/api/system/errors/route.ts`, cache the Sentry response in-memory (module-level `Map` with TTL 15-30s) so bursts of polls collapse to one upstream call. Match the BFF cache TTL to slightly less than the client poll cadence.
**Warning signs:** Sentry 429s visible in FastAPI logs; bill alerts.

## Code Examples

### PHI scrubber (TypeScript, key-based, recursive)

```typescript
// lib/sentry/phi-scrubber.ts
import type { Event } from "@sentry/nextjs";

const DENY_KEYS = new Set<string>([
  "patient_id", "mrn", "dob", "date_of_birth", "ssn",
  "first_name", "last_name", "full_name", "patient_name",
  "phone", "email", "address", "street", "zip", "postal_code",
  "insurance_number", "member_id", "policy_number", "group_number",
  "chief_complaint", "hpi", "assessment", "plan", "soap_text",
  "ai_summary_text", "note", "notes",
  // camelCase variants — Next.js frontend uses camelCase
  "patientId", "dateOfBirth", "firstName", "lastName", "fullName",
  "patientName", "postalCode", "insuranceNumber", "memberId",
  "policyNumber", "groupNumber", "chiefComplaint", "soapText", "aiSummaryText",
]);
const REDACTED = "[Filtered]";

function scrubValue(v: unknown): unknown {
  if (v === null || v === undefined) return v;
  if (Array.isArray(v)) return v.map(scrubValue);
  if (typeof v === "object") return scrubObject(v as Record<string, unknown>);
  if (typeof v === "string") return scrubUrlQuery(v);
  return v;
}

function scrubObject(obj: Record<string, unknown>): Record<string, unknown> {
  const out: Record<string, unknown> = {};
  for (const [k, v] of Object.entries(obj)) {
    if (DENY_KEYS.has(k)) { out[k] = REDACTED; continue; }
    out[k] = scrubValue(v);
  }
  return out;
}

function scrubUrlQuery(s: string): string {
  // Only rewrite if it looks like a URL with a query string
  const qi = s.indexOf("?");
  if (qi < 0) return s;
  try {
    const url = new URL(s, "http://placeholder.invalid");
    for (const key of Array.from(url.searchParams.keys())) {
      if (DENY_KEYS.has(key)) url.searchParams.set(key, REDACTED);
    }
    return url.toString().replace("http://placeholder.invalid", "");
  } catch { return s; }
}

export function scrubEvent(event: Event): Event | null {
  // event.request, event.extra, event.contexts, event.breadcrumbs
  if (event.request) event.request = scrubObject(event.request as Record<string, unknown>) as typeof event.request;
  if (event.extra) event.extra = scrubObject(event.extra) as typeof event.extra;
  if (event.contexts) event.contexts = scrubObject(event.contexts as Record<string, unknown>) as typeof event.contexts;
  if (event.breadcrumbs) {
    event.breadcrumbs = event.breadcrumbs.map(b => ({
      ...b,
      data: b.data ? scrubObject(b.data) : b.data,
      message: typeof b.message === "string" ? scrubUrlQuery(b.message) : b.message,
    }));
  }
  // user context — strip everything except id/role
  if (event.user) {
    event.user = {
      id: (event.user as { id?: string }).id,
      // role lives in event.tags or extra; we don't echo PII fields
    };
  }
  return event;
}
```

### Health endpoint (FastAPI)

```python
# backend/api/routes/system.py
import time
import httpx
from fastapi import APIRouter, Depends, Request
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncSession

from backend.core.rate_limit import check_rate_limit  # factored from public_booking.py
from backend.db.session import get_db
from backend.schemas.system import HealthResponse, DependencyStatus

router = APIRouter(prefix="/system", tags=["system"])

@router.get("/health/", response_model=HealthResponse)
async def get_health(request: Request, db: AsyncSession = Depends(get_db)):
    check_rate_limit(request.client.host)

    # Postgres probe
    pg_start = time.perf_counter()
    pg_status = "ok"
    try:
        await db.execute(text("SELECT 1"))
    except Exception:
        pg_status = "down"
    pg_latency_ms = int((time.perf_counter() - pg_start) * 1000)

    # Supabase probe — public well-known, no auth needed
    supa_start = time.perf_counter()
    supa_status = "ok"
    try:
        async with httpx.AsyncClient(timeout=2.0) as c:
            r = await c.get(f"{settings.SUPABASE_URL}/.well-known/openid-configuration")
            if r.status_code != 200: supa_status = "degraded"
    except Exception:
        supa_status = "down"
    supa_latency_ms = int((time.perf_counter() - supa_start) * 1000)

    return HealthResponse(
        api="ok",
        postgres=DependencyStatus(status=pg_status, latency_ms=pg_latency_ms),
        supabase_auth=DependencyStatus(status=supa_status, latency_ms=supa_latency_ms),
        version=settings.GIT_SHA[:7],
        checked_at=datetime.utcnow().isoformat() + "Z",
    )
```

_pinger_task: asyncio.Task | None = None

@app.on_event("startup")

    if os.getenv("SENTRY_ENVIRONMENT") != "production":
        return
    global _pinger_task
    _pinger_task = asyncio.create_task(_health_pinger_loop())

async def _health_pinger_loop():
    while True:
        try:
            await sample_health_now()  # writes one row to system_health_samples
        except Exception:
            pass  # never crash the loop; Sentry will capture real exceptions
        await asyncio.sleep(60)

@app.on_event("shutdown")
async def _stop_health_pinger():
    if _pinger_task:
        _pinger_task.cancel()

### Sentry REST proxy (BFF with caching)

```typescript
// app/api/system/errors/route.ts
import { NextRequest, NextResponse } from "next/server";

let cache: { at: number; payload: unknown } | null = null;
const TTL_MS = 20_000;

export async function GET(req: NextRequest) {
  // Auth — OWNER only. Read session from cookie via supabase server client.
  // ...role check...
  if (cache && Date.now() - cache.at < TTL_MS) return NextResponse.json(cache.payload);

  const org = process.env.SENTRY_ORG!;
  const project = process.env.SENTRY_PROJECT!;
  const token = process.env.SENTRY_API_TOKEN!;
  const r = await fetch(
    `https://sentry.io/api/0/projects/${org}/${project}/issues/?query=is:unresolved&limit=50&environment=production`,
    { headers: { Authorization: `Bearer ${token}` }, cache: "no-store" },
  );
  const data = await r.json();
  cache = { at: Date.now(), payload: data };
  return NextResponse.json(data);
}
```

### Uptime SQL (7-day rolling window)

```sql
SELECT
  count(*) FILTER (WHERE all_green) * 100.0 / NULLIF(count(*), 0) AS uptime_pct,
  count(*)                                                          AS samples_total,
  count(*) FILTER (WHERE all_green)                                 AS samples_green,
  min(checked_at)                                                   AS window_start,
  max(checked_at)                                                   AS window_end
FROM system_health_samples
WHERE checked_at >= now() - interval '7 days';
```

Add one such test per clinical prefix. This is the HIPAA seatbelt and MUST be in every PR's diff if it touches the scrubber.
