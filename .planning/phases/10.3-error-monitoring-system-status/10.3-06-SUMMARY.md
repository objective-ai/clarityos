## HealthDot Component Tree

```
TopNav (header)
  └─ action cluster (right side)
       ├─ <HealthDot />          [OWNER-only, 60s poll, colored dot]
       ├─ <ClockInButton />
       ├─ Theme toggle
       └─ Logout
```

`HealthDot` internals:
- `useSession()` → `session?.user?.role === "owner"` (lowercase — matches `StaffRole` type union)
- Early return `null` for non-owners (no DOM at all)
- `useEffect`: `load()` immediately + `setInterval(load, 60_000)`; cleanup clears interval + sets `ok = false` flag to drop in-flight `then` callbacks
- Rollup: `["api", "postgres", "supabaseAuth"].some(v === "down") ? red : some("degraded") ? amber : green`
- Click: `router.push(\`/${useParams().tenant}/admin?section=system\`)`

## SystemStatusSection Component Tree

```
SystemStatusSection (30s poll clock owner)
  ├─ header
  │    ├─ "System Status" title
  │    └─ Updated HH:MM:SS · Refresh button
  ├─ ServiceHealthPanel (refreshKey)
  │    └─ grid-cols-3: FastAPI · Postgres · Supabase Auth
  ├─ RecentErrorsPanel (refreshKey)
  │    └─ table: Title · Count · Last Seen · Env
  └─ UptimePanel (refreshKey)
       └─ grid-cols-4: Uptime % · Samples · Window Start · Window End
```

Each panel owns its own `useEffect` + `fetch` and re-runs on `refreshKey` change. `SystemStatusSection` bumps `refreshKey` on both the 30s interval and the manual Refresh click — a single clock drives all three panels coherently.

## Decisions Made

- **OWNER-only all the way down:** Backend `PERMISSION_MATRIX` grants `VIEW_SYSTEM_STATUS` only to `UserRole.OWNER`. Frontend entitlement map mirrors that — even if JWT `app_metadata.entitlements` is empty, `PLAN_FEATURES[planName]` still exposes the key to owners. Non-owner clients get no section in the sidebar AND no leak via deep link.
- **'Not available' instead of 403 for deep link:** A 403 screen would confirm the route exists. Rendering a neutral "Not available" glass-card keeps the feature invisible to technicians/receptionists.
- **Split poll cadence — 30s admin, 60s topnav:** Admin panel is visible when the OWNER is actively looking; topnav dot is always visible. 60s is enough granularity for "something's off, go look" while being half the request volume.
- **Red wins ties in dot color rollup:** Any 'down' dep paints the dot red even if others are 'ok' — the OWNER wants the worst-case signal, not an average.
- **`HealthDot` uses `useParams()` not a hardcoded route:** Matches the `[tenant]` folder convention — a single `<HealthDot />` component works for every tenant.
- **No props-drilling for session:** `HealthDot` calls `useSession()` directly (Zustand store). TopNav doesn't know or care about roles — the dot self-hides.
