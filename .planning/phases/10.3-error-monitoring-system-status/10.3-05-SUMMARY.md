# Phase 10.3 Plan 05: Uptime Endpoint + Sentry Errors Proxy Summary

One-liner: 7-day rolling uptime endpoint in FastAPI plus a BFF proxy to
the Sentry Issues REST API with OWNER-gate and 20s in-memory cache,
shipping the camelCase TypeScript types the System Status page will
consume.

## What Was Built

### Task 1 — Uptime endpoint + Pydantic schemas + unit tests (commit 88a679c)

- `backend/schemas/uptime.py` — `UptimeSummary`, `ErrorIssue`,
  `ErrorIssueList` Pydantic models (BaseModel, snake_case — the BFF
  renames to camelCase at the TypeScript boundary).
- `backend/api/routes/uptime.py` — standalone FastAPI router exposing
  `GET /api/system/uptime/` (trailing slash per project rules). Uses a
  private SQLAlchemy Core `Table` descriptor against
  `public.system_health_samples` so it does not depend on Plan 04's ORM
  model import.

  **Final uptime SQL (portable form — used in production):**
  ```sql
  SELECT count(id)                                         AS total,
         count(nullif(all_green, false))                   AS green,
         min(checked_at)                                   AS window_start,
         max(checked_at)                                   AS window_end
  FROM public.system_health_samples
  WHERE checked_at >= :cutoff   -- cutoff = now() - 7 days
  ```

  Uptime % = `round(green / total * 100, 2)` when `total > 0`, else
  `0.0`. Zero-division is guarded. Window bounds render ISO UTC with
  `Z` suffix; both are `null` when there are no samples.

- `backend/main.py` — registers `uptime.router` at prefix
  `/api/system`. Shares the prefix cleanly with Plan 04's `system`
  router (they use distinct paths `/uptime/` vs `/health/`).

- `backend/tests/test_uptime.py` — **6 pytest cases, all green:**
  1. 10 green + 2 red → `uptime_pct ≈ 83.33`, `samples_total=12`,
     `samples_green=10`, window bounds ISO Z.
  2. Compiled SQL contains `system_health_samples`, `checked_at`, and
     a `WHERE` clause — proves the 7-day cutoff is wired.
  3. Zero samples → `uptime_pct=0.0`, no `ZeroDivisionError`, null
     window bounds.
  4. All green → 100%.
  5. All red → 0%.
  6. Table descriptor exposes `{id, checked_at, all_green}` in the
     `public` schema.

### Task 2 — BFF proxies + TS types + vitest (commit 060f9fb)

- `app/api/system/uptime/route.ts` — 8-line `proxyToFastAPI(req, "/api/system/uptime/")`.
- `app/api/system/errors/route.ts` — 120-line Sentry REST proxy.

  **Exact Sentry URL called:**
  ```
  https://sentry.io/api/0/projects/${SENTRY_ORG}/${SENTRY_PROJECT}/issues/
    ?query=is:unresolved&limit=50&environment=production
  ```

  With header `Authorization: Bearer ${SENTRY_API_TOKEN}` and
  `cache: "no-store"` on the upstream fetch.

  - **OWNER gate:** `createServerSupabaseClient().auth.getUser()` →
    read `app_metadata.role`. Anything other than `"OWNER"` returns
    `403 {"error":"forbidden"}` — **before** any fetch, so non-OWNER
    clients cannot trigger upstream load.
  - **Cache:** module-level slot, `TTL_MS = 20_000`. Second call
    within window returns `{ ...cached, cached: true }`; after 20s the
    upstream is hit again and `cached: false`.
  - **Token safety:** `SENTRY_API_TOKEN` is read from `process.env`
    server-side only; never echoed in the response body. Tests assert
    the literal token string and the word `Bearer` are absent from the
    response text.
  - **Soft-fail:** upstream 4xx/5xx, network errors, and missing env
    vars all return `200` with `{ issues: [], fetchedAt, cached: false }`
    plus an `x-sentry-upstream-status` header (`503`, `network-error`,
    `not-configured`) so the UI can flag the issue without breaking.
  - **Exports `__resetCache()`** so vitest can reset module state
    between tests.

- `types/system.ts` — `DependencyStatus`, `HealthResponse`,
  `UptimeSummary`, `ErrorIssue`, `ErrorIssueList`. All camelCase.

- `tests/unit/sentry-errors-proxy.test.ts` — **9 vitest cases, all green:**
  1-3. OWNER gate: no session → 403; `role: doctor` → 403 + no
  upstream call; `role: OWNER` → 200 + upstream called once.
  4-5. Cache: two calls within 20s → upstream called once, second call
  has `cached: true`; advancing `Date.now()` by 21s → upstream called
  twice.
  6-7. Token safety: response body contains neither `SECRET_TOKEN_ABC`
  nor `Bearer`; upstream `Authorization` header IS `Bearer SECRET_TOKEN_ABC`.
  8-9. Upstream failure: Sentry 503 → 200 with `x-sentry-upstream-status: 503`
  + empty issues; missing env var → `x-sentry-upstream-status: not-configured`.

## Deviations from Plan

### [Rule 3 — Parallel-plan file contention] Split schemas/routes into dedicated files

- **Found during:** Task 1 planning (before writing any code).
- **Issue:** Plan 10.3-04 (same wave) also edits
  `backend/schemas/system.py` and `backend/api/routes/system.py`. The
  parallel_context directive in the spawn prompt explicitly called out
  the collision risk and suggested standalone modules.
- **Fix:** Authored standalone `backend/schemas/uptime.py` and
  `backend/api/routes/uptime.py`. Uptime router registered in
  `backend/main.py` with prefix `/api/system`, sharing the prefix with
  Plan 04's `system` router (distinct paths — zero conflict).
- **Acceptance-criteria impact:** plan's automated verify grep checks
  `grep -q 'class UptimeSummary' schemas/system.py` etc. — these fail
  against `schemas/system.py` but pass against `schemas/uptime.py`.
  Functional intent of the plan is fully satisfied; only the file
  location differs. Intentional + pre-approved by the spawn prompt.
- **Commit:** 88a679c

### [Rule 3 — Missing test infrastructure] Uptime test uses fake AsyncSession

- **Found during:** Task 1.
- **Issue:** Plan specified `async_db` pytest fixture against a real
  test database. `backend/tests/` has no `conftest.py` and no async DB
  fixture; building one requires a dedicated test DB + Alembic
  bootstrapping + `pytest-asyncio` plugin — all out of scope and
  blocked on Plan 04's migration landing.
- **Fix:** Wrote pure-unit tests with a fake `AsyncSession` stub that
  returns a pre-built aggregate row. This exercises the handler's
  computation (ratio, rounding, ISO formatting, zero-guard) and the
  SQL shape (table name, columns, WHERE clause) via compiled-SQL
  introspection. Real-DB integration is implicitly covered by Plan 04's
  migration + Plan 06's smoke test of the same endpoint.
- **Commit:** 88a679c

### [Plan-prescribed] Sentry proxy tests relocated from pytest → vitest

- **Issue:** Plan frontmatter declared
  `backend/tests/test_sentry_errors_proxy.py`. The code under test is
  a TypeScript Next.js route handler; pytest cannot exercise it.
- **Fix:** Wrote the tests as `tests/unit/sentry-errors-proxy.test.ts`
  (vitest). Plan 10.3-05 Task 2 spec explicitly RECOMMENDED this
  relocation, so it is plan-prescribed rather than an auto-fix.
- **Commit:** 060f9fb

### [Scope-boundary] Pre-existing TS errors logged to deferred-items
