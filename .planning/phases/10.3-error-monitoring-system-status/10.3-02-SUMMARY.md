# Phase 10.3 Plan 02: Sentry Next.js Wire-up Summary

JWT-safe Sentry instrumentation across Next.js browser/server/edge runtimes with PHI scrubber delegation and prod-only gate.

## What Was Built

### Task 1: Install @sentry/nextjs + env stubs (prior agent — commit 55881fc)

- Installed `@sentry/nextjs@^8.0.0` (resolved to v8.55.1 per `node_modules/@sentry/nextjs/package.json`).
- Appended `.env.example` with 7 env stubs: `NEXT_PUBLIC_SENTRY_DSN`, `SENTRY_DSN`, `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_ENVIRONMENT`, `SENTRY_API_TOKEN`.

### Task 2: Three runtime configs + instrumentation hook (commit 7762415)

Four files at repo root:

- **`sentry.client.config.ts`** — browser init. Reads `NEXT_PUBLIC_SENTRY_DSN` + `NEXT_PUBLIC_VERCEL_ENV`. Prod-only. Replay sample rates 0.0. `ignoreErrors: ["NEXT_REDIRECT"]`. `beforeSend: scrubEvent`.
- **`sentry.server.config.ts`** — Node route handler init. Reads `SENTRY_DSN` + `VERCEL_ENV` (fallback to public). Same scrubEvent wiring.
- **`sentry.edge.config.ts`** — edge runtime init. Same gate, same scrubEvent.
- **`instrumentation.ts`** — Next.js 14 App Router hook. Routes by `NEXT_RUNTIME` to `./sentry.server.config` or `./sentry.edge.config`.

Each config gates on `dsn && vercelEnv === "production"` — dev + preview deploys never init Sentry.

### Task 3: Wrap next.config.mjs with withSentryConfig (commit 951a668)

- Discovery: project uses `next.config.mjs` (ES modules), not `.js`. Used `import { withSentryConfig } from "@sentry/nextjs"` at top.
- All existing security headers preserved (CSP, X-Frame-Options, Permissions-Policy, etc — **no regression**).
- withSentryConfig options: `org`, `project`, `authToken` from env; `silent: !process.env.CI`; `widenClientFileUpload: true`; `hideSourceMaps: true`; `disableLogger: true`; `tunnelRoute: "/monitoring-tunnel"`.
