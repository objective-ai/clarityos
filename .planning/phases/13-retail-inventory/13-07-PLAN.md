<objective>
Extend the Phase 6 optical-queue loop in `backend/api/routes/optical.py` so each `OpticalQueueItem.status` is computed from any related `OpticalOrder` rows for that encounter, falling back to `Encounter.optical_status` when no live orders exist. The Phase 6 `Encounter.optical_status` column is NOT modified — only the queue API's response status is overridden when Phase 13 orders supply a more authoritative state.

Purpose: Without this rollup, an encounter with a `placed` optical order would still display Phase 6's manually-set status, causing the optical-queue card to mislead staff. CONTEXT §C explicitly requires this rollup AND says Phase 14 must respect it.

Output: Single-file edit in `backend/api/routes/optical.py`. Adds `selectinload(Encounter.optical_orders)` to the queue query so no N+1, and a 5-line rollup computation block.
</objective>
