# Phase 12 — UI Design Contract: CRM & Patient Engagement

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value | Source |
|----------|-------|--------|
| Tool | none — manual glassmorphism component system | codebase (globals.css, components/ui/) |
| Preset | not applicable | no components.json |
| Component library | Radix UI (Slot, Dialog, DropdownMenu, Accordion via components/ui/) | components/ui/*.tsx |
| Icon library | lucide-react | app/**/*.tsx grep |
| Font | Plus Jakarta Sans (`var(--font-jakarta)`) | tailwind.config.ts + globals.css |
| Monospace font | `var(--font-mono)` — for message character counts and timestamps | globals.css |

**Design language:** Glassmorphism dark UI. All new surfaces use `.glass-card` base class with `backdrop-filter: blur(16px)` and `border: 1px solid var(--glass-border)`. Public-facing signed-token pages (channel preference self-service, confirm/reschedule links) override to light theme using `data-theme="public-booking"` pattern — matching Phase 10.2 precedent.

## Spacing Scale

Declared values (multiples of 4 only):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, status icon spacing, inline badge padding |
| sm | 8px | Compact row padding, chip gap, inline element spacing |
| md | 16px | Default card padding, form field spacing, composer gutter |
| lg | 24px | Card section padding (CardHeader p-6 = 24px, existing pattern) |
| xl | 32px | Page section breaks, wizard step padding |
| 2xl | 48px | Major section separation (analytics page) |
| 3xl | 64px | Page-level top padding |

Exceptions:
- **Touch targets:** 44px minimum (`var(--touch-target)`) — composer Send button, inbox item tap target, recall queue row action buttons. Enforced via `min-h-[var(--touch-target)]`.
- **Wizard step height:** Each wizard step content area has `min-height: 200px` to prevent layout shift between steps.
- **Message status icon cluster:** 20px width per icon — tighter than xs to fit Queued/Sent/Delivered/Read/Failed in a timeline row.

| Subhead | `.text-subhead` | 16px | 600 | 1.4 | Card titles, composer section labels, wizard step titles |

## Color

All values are CSS custom properties from globals.css. Do not hardcode hex values in new components — reference the token.

| Role | Token | Dark Value | Usage |
|------|-------|-----------|-------|
| Dominant (60%) | `var(--bg-base)` / `var(--bg-surface)` | `#06080D` / `#0C0F16` | Page background, full-page layouts |
| Secondary (30%) | `var(--bg-elevated)` / `var(--bg-overlay)` | `#12151E` / `#1A1D28` | Glass cards, inbox rows, recall queue rows, composer surface, wizard step containers |
| Accent (10%) | `var(--accent)` | `#2DD4BF` | See reserved-for list below |
| Destructive | `var(--state-critical)` | `#F87171` | Opt-out warnings, failed message state, hard-stop cost cap alert, delete template action |
| Warning | `var(--state-warning)` | `#FBBF24` | 80% cost cap threshold warning, PHI keyword scan soft-warn in SMS composer, quiet-hours deferral notice |
| Success | `var(--state-normal)` | `#34D399` | Message delivered state, confirmed appointment indicator, opt-in consent captured |
| Info | `var(--state-info)` | `#60A5FA` | Queued message state, AI classification tags, inbound message badge |

**Accent (`#2DD4BF`) reserved for:**
1. Primary CTA buttons: "Send Message", "Send All" (recall queue), "I received them" (wizard completion), "Draft with AI"
2. Active wizard step indicator dot / progress line
3. Unread inbox badge count on TopNav
4. Message delivered double-checkmark icon (delivery confirmed state)
5. Channel preference chip border-glow when both channels are active
6. Recall queue "Send All" row — left-border accent stripe (matching nav-item.active pattern)
7. Focus rings on all composer inputs

**Accent is NOT used for:** generic row hover states, info tags, AI classification labels, timestamps, or disabled state elements.

## Page-Level Layout Contracts

### `/messaging/inbox` — Global Inbound Inbox

- Layout: two-column on desktop (inbox list left 380px, message thread right flex-1), single column on mobile
- Left panel: search bar at top (glass-input), filter tabs (All / Reschedule / Cancellation / Other), scrollable `InboxItem` list
- Right panel: per-patient thread view, chronological message bubbles (sent = right-aligned teal, received = left-aligned glass), reply `MessageComposer` pinned to bottom
- Unread count badge: TopNav messaging icon with accent-colored numeric badge (max display "99+")
- Empty state: centered illustration placeholder + "No messages yet — reminders and replies will appear here"

### `/messaging/recall-queue` — Staff-Approved Recall Queue

- Layout: full-width table with sticky header row, filter bar at top
- Table columns: Patient name + last visit date | Preferred channel | Consent status | Message preview (truncated) | Actions (Send / Remove)
- Bulk action bar: appears above table when 1+ checkboxes checked — "Send Selected (N)" button + "Remove from Queue" ghost button
- Mandatory preview-confirm `Dialog` before any send: shows rendered message, recipient count, estimated cost, opt-out exclusions count
- Auto-exclusion chips below table header: "12 excluded — deceased / opted-out / future appt" (clicking expands list in Dialog)
- Empty state: "No patients due for recall — patients with no visit in 12+ months will appear here"

### `/messaging/analytics` — Messaging Analytics

- Layout: mirrors `app/(tenant)/[tenant]/analytics/page.tsx` exactly — inline Recharts, no extracted chart components (SSR safety — memory note)
- Date range selector: 7d / 30d / 90d / YTD / Custom (matches Phase 8 pattern)
- 4 chart sections:
  1. Reminder funnel (stacked bar: sent → delivered → confirmed → kept)
  2. Recall conversion (line chart: sent → booked within 14/30/90 days, 3 lines)
  3. Opt-out trend (area chart: weekly opt-out count with amber threshold line)
  4. Cost & volume (grouped bar: SMS count / email count + line overlay for $ spend vs cap)
- Export buttons: CSV per chart (ghost button, Download icon), "Compliance Report PDF" (outline button, OWNER-gated with `useEntitlements().has('messaging_compliance_export')`)

### `/settings/messaging/onboarding` — 7-Step Wizard

- Layout: centered single-column card (max-width 640px), progress dots at top (7 dots, active = accent filled, completed = accent outlined, future = muted)
- Each step: `WizardStep` card with step number overline, title (`.text-subhead`), body instruction (`.text-body`), action area at bottom
- Navigation: "Back" ghost button left + "Continue" default button right in each step footer
- Step 7 completion: test-message send triggers a "Sending test..." loading state on button → success state ("I received them" replaces Continue) — only this confirm flips `clinic_messaging_enabled`
- Error recovery in wizard: inline error below field (not toast), red border on invalid input

### `/settings/messaging` — Templates & Settings

- Layout: two tabs (Templates / Preferences) using existing tab pattern
- Templates tab: list of templates per type (reminder / recall / manual), per-row edit body text inline (glass-input), language switcher chip (EN / ES) per template
- Preferences tab: cost cap slider (daily $25 default), quiet hours display (read-only in v1 — 9pm–8am), messaging enabled toggle

## Interaction Contracts

### MessageComposer

1. **Open trigger:** Patient header "Message" button, schedule kebab "Message Patient", inbox reply area, bulk-select toolbar
2. **Initial state:** Channel selector (SMS / Email / Both) defaults to patient's preferred channel. If opted out → channel greyed with `OptOutWarning` and send blocked.
3. **Template selection:** Dropdown of 5–7 templates. On select: body pre-fills with tokens replaced (first name, appt time etc.). Body is editable after pre-fill.
4. **SMS preview:** Below body field — live character count in `.font-mono-data` format "142 / 160 chars (1 segment)" — updates on every keystroke. Goes amber at 141+, red at 301+ (2+ segments).
5. **PHI scan (SMS only):** On every body change, scan for keywords (Rx values regex, ICD-code pattern, diagnosis terms). If match found: amber banner "SMS is less secure — this message may contain clinical details. Continue?" with "Send Anyway" (outline) and "Edit Message" (ghost) options inside composer. Does NOT block send — soft confirm only.
6. **"Draft with AI" button:** Opens a plain-text intent input ("What do you want to tell the patient?") with a "Generate" button. On submit: loading spinner on button + disabled body field → response streams into body field. Staff edits freely.
7. **Send button:** Disabled until (a) body is non-empty, (b) at least one valid channel selected, (c) opt-out gate passes. On click: shows loading state (spinner icon replaces Send text). On success: composer closes + success toast "Message sent to [First Name]". On failure: inline error in composer (no close).
8. **Bulk send (schedule view):** Same composer but recipient count shown at top "Sending to 12 patients". Max 50 enforced client-side with error if exceeded. Preview-confirm Dialog required before final send.

### Message Status Icons (MessageStatusIcon)

| State | Icon (Lucide) | Color | Tooltip |
|-------|--------------|-------|---------|
| Queued | `Clock` | `var(--text-muted)` | "Queued — scheduled to send" |
| Sent | `Check` | `var(--text-secondary)` | "Sent [timestamp]" |
| Delivered | `CheckCheck` | `var(--accent)` | "Delivered [timestamp]" |
| Read (email) | `Eye` | `var(--state-info)` | "Opened [timestamp]" |
| Failed | `XCircle` | `var(--state-critical)` | "[Failure reason] — Resend?" |

Failed state includes inline "Resend" text button (link variant, accent color) at the end of the icon row.

### Wizard Step Transitions

- Steps advance via "Continue" button only (no click-outside navigation).
- Completed steps show green checkmark icon on progress dot.
- Step 3 (number provisioning): async Twilio call during Continue press — button shows spinner, step does not advance until provisioning resolves. On failure: inline error "Number provisioning failed — try again" with retry button.
- Step 7 (test send + confirm): "Send Test Message" triggers send to OWNER phone+email. Button state: idle → sending (spinner) → success (CheckCircle icon, button text "Resend if needed"). "I received them" button appears only after test-send success and activates `clinic_messaging_enabled=true`.

### Recall Queue Actions

- Per-row "Send" button (outline, small): opens preview Dialog for that single patient. Confirm → sends and removes row from queue with fade-out animation.
- Per-row "Remove" button (ghost, small, destructive color): removes from queue immediately without confirm (non-destructive — patient still exists, just removed from this run).
- "Send All" button (default, accent): triggers mandatory preview Dialog showing: recipient count, total estimated cost vs cap, opt-out exclusion count. Confirm triggers batch send with `batch_id`.
- After Send All: progress indicator replaces button ("Sending 23 / 31...") with cancel option. On completion: success state with summary.

## Accessibility Contracts

- All icon-only buttons (status icons, send icon, compose trigger) have `aria-label` describing the action.
- Composer textarea has `aria-label="Message body"` and `aria-describedby` pointing to character count element.
- Wizard steps use `role="progressbar"` on the progress dot container with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`.
- Recall queue table uses `<table>` semantics with `<caption>` for screen readers.
- Opt-out warning is `role="alert"` so it is announced immediately on render.
- Cost cap hard-stop toast is `role="alert" aria-live="assertive"`.
- Dialog modals trap focus and return focus to trigger on close.
- Color is never the sole differentiator — message status uses icon + color (not color only).

## Public-Facing Pages (Signed Token, No Auth)

Two pages use the light theme override (matching Phase 10.2 public booking pattern):

1. **Confirm/Reschedule page** (`/confirm/[token]`) — patient taps link from reminder SMS/email. Shows appointment summary (date, time, provider, clinic name — NO diagnosis/Rx). Two large touch-target buttons: "Confirm Appointment" (accent) and "Request Reschedule" (outline).

2. **Channel preference self-service** (`/preferences/[token]`) — patient manages their own opt-in/out and pause-until-date. Must use `data-theme="public-booking"` attribute + explicit Tailwind classes (`bg-white`, `text-gray-900`) — NOT CSS variable references that leak glassmorphism dark values (Phase 10.2-06 precedent).

Both pages: max-width 480px, centered, mobile-first, no TopNav/Sidebar.
