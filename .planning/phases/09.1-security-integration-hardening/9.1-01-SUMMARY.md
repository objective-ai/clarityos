# Phase 9.1 Plan 01: Auth Hardening (api-client + middleware) Summary

**One-liner:** JWT auth headers added to two unauthenticated BFF fetch calls, and middleware blanket /api/* exemption replaced with an explicit public-route allowlist.

## What Was Built

**Task 1 — api-client.ts:** `fetchPatientInsurance` and `fetchSuperbillPdfBlob` both now call `getAuthHeaders()` and pass the JWT bearer token. Raw `fetch()` is retained (not replaced with `apiFetch`) because: (a) insurance response must stay snake_case to match the `PatientInsurance` type, and (b) the PDF endpoint returns a `Blob`, not JSON. Both functions now also have try/catch guards returning safe empty values on failure.

**Task 2 — middleware.ts:** The blanket `pathname.startsWith("/api")` exclusion is replaced with two specific exemptions: `/api/public/` (intake token and booking routes) and `/api/address/` (Google Places autocomplete for the public intake form). All other `/api/*` routes now run through auth verification at the middleware layer, providing defense-in-depth alongside `proxyToFastAPI()`.
