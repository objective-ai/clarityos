# Phase 10.1: Insurance Revamp - Context

**Gathered:** 2026-03-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Enrich patient insurance records with missing production fields: copay amount, authorization code, eligibility status, and active/inactive flag. Surface insurance summary (copay + eligibility) in encounter header and schedule view. No document upload (V3-08), no coinsurance/deductible (V3-02), no electronic eligibility verification API.

</domain>

<decisions>
## Implementation Decisions

### Copay & Cost-sharing
- Single flat copay dollar amount per insurance record (`copay_amount DECIMAL`)
- NOT per-visit-type (routine vs medical) — one amount, staff overrides at checkout if needed
- Coinsurance and deductible remain deferred to V3 with ERA/EOB integration
- Surface copay in: Insurance Tab card, encounter header chip, superbill/billing view

### Eligibility Tracking
- 5-state enum: `active`, `inactive`, `pending_verification`, `expired`, `unknown`
- Default for new records: `unknown`
- `eligibility_verified_date` field — date of last manual verification
- Stale indicator if verified date > 30 days old
- Surface eligibility in: Insurance Tab card, encounter header chip, schedule view badge

### Authorization
- Auth stored at BOTH levels: default on PatientInsurance record, overridable per encounter
- Three auth fields on PatientInsurance: `auth_number` (string), `auth_expiry` (date), `auth_services` (text — e.g. "6 visits" or "contact lens fitting")
- Per-encounter override: auth fields on encounter or encounter-insurance junction (researcher to determine best approach)
- Auth info displayed on insurance card in Coverage section

### Active/Inactive Flag
- `is_active` boolean on PatientInsurance, default `true`
- Inactive records: dimmed + moved to "Past Insurance" section below active cards
- Unique constraint changes: partial unique on `(patient_id, priority) WHERE is_active = true`
  - Allows historical inactive records with same priority
  - Only ONE active primary + ONE active secondary at a time

### Insurance Summary Badges
- Compact colored chips in encounter header: `[VSP * $25 checkmark]` format
- Same chips on schedule view next to patient name
- Chips show: payer short name, copay amount, eligibility status dot
- Color-coded eligibility: green=active, red=inactive, yellow=pending, gray=unknown, orange=expired

### Card Layout (Insurance Tab)
- Grouped sections within each insurance glass card:
  1. **Header**: Priority badge + payer name + active/inactive status
  2. **Plan Info**: Plan type, subscriber ID, group number, plan name (2-column grid)
  3. **Coverage**: Copay, eligibility status, verified date, auth number + expiry (2-column grid)
  4. **Subscriber**: Relationship, subscriber name, DOB (shown when relationship != self)
- Inactive cards: grayed out, moved to "Past Insurance" section below active cards

### Form Modal
- Single scrollable form (no wizard/tabs)
- Section dividers grouping: Plan Info, Coverage Details, Subscriber Info
- New fields added: copay amount, eligibility status, verified date, auth number, auth expiry, auth services, is_active toggle

### Claude's Discretion
- Exact chip/badge styling and color values
- Stale verification threshold (suggested 30 days but flexible)
- Auth services field — free text vs structured
- Per-encounter auth override implementation approach (junction table vs encounter fields)
- Empty state text for new fields

</decisions>
