# Phase 10.1 Plan 03: Insurance Surface Summary

Insurance summary data surfaced in three clinical locations: encounter header chips, schedule eligibility badges, and billing copay display.

## What Was Built

**TopNav (encounter header):** Replaced plain "P: PayerName / S: PayerName" text with compact glassmorphism chips. Each chip shows: colored eligibility dot (emerald=active, red=inactive, yellow=pending, orange=expired, gray=unknown), truncated payer name (first word if >12 chars), and copay amount on primary. Only `is_active=true` insurance shown. Defined `ELIG_DOT` color map at file top.

**Schedule view badges:** Added `SCHED_ELIG_DOT` color map and compact eligibility badge to `AppointmentCard.tsx` — renders next to patient name. Backend `list_appointments` now batch-fetches primary active insurance for all patient IDs in one query (avoids N+1), maps to `ins_by_patient` dict, then passes insurance to `_build_appointment_response`. Three new fields on `AppointmentResponse`: `insurance_payer_name`, `insurance_copay`, `insurance_eligibility`. TypeScript `Appointment` interface extended with `insurancePayerName`, `insuranceCopay`, `insuranceEligibility`.

**Billing copay:** `BillingWorkflow` derives `primaryCopay` from the already-loaded `insurancePlans` state by matching `payer_id` to `superbill.billedPayerId`. Renders "Copay: $XX.XX" inline in the payer row in accent color — no additional fetch required.

## Deviations from Plan

**1. [Rule 2 - Enhancement] Eligibility badge placed in AppointmentCard, not schedule/page.tsx**
- **Found during:** Task 2
- **Issue:** The plan suggested adding badges to `schedule/page.tsx`, but the page delegates all appointment row rendering to `AppointmentCard`, `TimelineView`, and `ClinicView`. Adding it only to page.tsx would only cover the fallback list view mode.
- **Fix:** Added `SCHED_ELIG_DOT` and badge directly to `AppointmentCard.tsx` — covers all three view modes since they all use the card's data shape.
- **Files modified:** components/schedule/AppointmentCard.tsx (instead of schedule/page.tsx)

**2. [Rule 2 - Enhancement] BillingWorkflow copay derived from existing state**
- **Found during:** Task 3
- **Issue:** Plan suggested adding a new `useEffect` fetch for insurance. `BillingWorkflow` already fetches all patient insurance into `insurancePlans` state on mount.
- **Fix:** Derived `billedPlan` by matching `payer_id` to `superbill.billedPayerId` — zero additional fetches, always in sync with payer dropdown selection.
