This is a **documentation and verification gap**, not necessarily a code quality gap. The phases were executed and committed, but the verification step was skipped for 7 of 8 phases.

## Integration Check

### Wiring: 56/57 BFF routes confirmed wired via `proxyToFastAPI`

All 57 BFF routes use `proxyToFastAPI` (137 call sites across 57 files). One route (`/api/encounters/[id]/superbill/pdf`) uses raw `fetch()` intentionally — binary PDF streaming would be corrupted by JSON parsing in `proxyToFastAPI`. That route has manual auth checks.

| 1 | Login → Schedule → Check-in → Start Exam → Encounter → Finalize → Superbill → Billing | COMPLETE |
| 2 | Patient → Insurance → Encounter → Superbill → Fee auto-populate → CMS-1500 PDF | PARTIAL |
| 3 | Encounter finalize → Optical queue → Rx PDF | COMPLETE |
| 4 | Intake token → Patient form → Patient record → Triage badge | COMPLETE |
| 5 | Analytics dashboard real data | COMPLETE |
| 6 | Auth middleware on all clinical routes | COMPLETE (pattern risk) |

### Critical Findings

**1. Middleware bypasses auth for ALL `/api/*` paths (SEC-01/SEC-02)**
`lib/supabase/middleware.ts` line 59 excludes all `/api/*` from auth checks. Auth is delegated entirely to `proxyToFastAPI`. Currently safe because all 57 routes call `proxyToFastAPI` and the PDF route checks manually. But any future BFF route that omits auth is reachable unauthenticated with no safety net.

**2. `fetchPatientInsurance` uses raw `fetch()` (INS-03, BILL-04)**
`lib/api-client.ts` lines 134-139 uses raw `fetch()` without auth headers instead of `apiFetch`. Call works at runtime because BFF enforces auth, but silently returns `[]` if session cookie is missing.

**3. Fee catalog BFF route has no frontend consumer (INS-05, INS-06)**
`/api/fee-catalog/route.ts` BFF exists but `BillingWorkflow.tsx` does not call it. Superbill line items show `$0` until saved and server resolves via `fee_service.py`. UX gap, not data loss.

### All Requirements Wired

All 60 requirements have cross-phase integration wiring confirmed except INS-05/INS-06 (fee schedule UX gap). The integration checker confirmed all stores, BFF routes, and backend endpoints are connected end-to-end.
