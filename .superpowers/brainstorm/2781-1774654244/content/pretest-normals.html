Pre-Test "Normal" Defaults — Per-Doctor or Universal?

When a tech clicks "All Normal", what values should populate?

Currently, "All Normal" sets hardcoded values like PERRL: true, Confrontation: "Full", Motility: "Full", etc. But different doctors may have different expectations for what "normal" means in their workflow.

A

Universal Defaults (Current)

One set of "normal" values for the whole clinic. Simple. Works well for solo practice or clinics where all doctors agree on baseline normals.

Pros

  • Zero config needed
  • Already implemented
  • Consistent across techs

Cons

  • Doctor can't customize their own normals
  • May not match every doctor's charting style
B

Per-Doctor Normal Templates

Each doctor defines their own "normal" template. When the tech starts a pre-test, the defaults come from the assigned doctor's preferences.

Pros

  • Each doctor gets exactly their charting style
  • Scales to multi-doctor clinics

Cons

  • Needs a settings UI for doctors to configure
  • More complex — what if no doctor is assigned yet?
  • Overkill for solo practice pilot
C

Universal Now, Per-Doctor Later

Ship with universal defaults for the pilot. Design the data model so per-doctor templates can be added in a future phase without migration pain.

Pros

  • Ship fast for solo pilot
  • No wasted work — universal is the right v1
  • Easy upgrade path when multi-doctor needs arise

Cons

  • Multi-doctor clinics won't have customization on day one

💡 Recommendation: Option C — universal defaults are the right call for a solo optometrist pilot. Per-doctor templates are a natural Phase 11+ feature when you onboard multi-doctor clinics.
